# Admin Dashboard Experience Design

- **Intent:** Make the AlertBarangay admin dashboard easier to use and provide account, appearance, settings, announcements, and activity controls.
- **Goals:** Space user names and emails clearly; provide settings and support contact; let admins CRUD shared announcements; let each admin choose system/light/dark appearance; show live notifications for new accounts and announcements; provide profile edit and sign-out from the top-right avatar.
- **Non-goals:** Email or push delivery, resident-facing announcement UI in this standalone admin module, and changing roles or account authorization.
- **Constraints:** Continue using Next.js App Router and Supabase. Admin mutations must be server-authorized. Announcements must be queryable by connected dashboards after merge. Support contact defaults to the signed-in admin's email because no official support address is configured.
- **Approaches:** (1) Local-only demo state is quick but cannot share announcements or durable notifications. (2) Supabase-backed announcements and activity with Realtime provides shared, durable data and immediate updates; chosen because connected dashboards need to consume announcements. (3) Polling is simpler but delays updates and adds recurring requests.
- **Design:** Add secured admin routes for announcement CRUD and activity reads/acknowledgements; add SQL tables, indexes, and policies for published announcements and activity; track notification receipts per admin and emit account-created activity. Use a shared top-right control for activity, theme, and profile; persist theme preference locally. Add Settings and Announcements pages to the existing navigation. Allow profile display-name updates through the existing own-profile policy.
- **Builder calls:** Show newly created accounts and new announcements in the admin activity menu. Use the signed-in admin email in Settings as the available support contact. Announcements are shared as published records for connected dashboards to read.
